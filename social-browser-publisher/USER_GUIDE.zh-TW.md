# Social Browser Publisher 學員使用手冊

版本：v1.1.1  
適用平台：Instagram、Facebook、Threads  
使用方式：Codex + 已登入的 Google Chrome

線上閱讀：[Notion 完整手冊](https://app.notion.com/p/3cf4e6997823811b9fe8ce35b7b9989c?pvs=204)

> 一個 Skill 完成「找題材、學語氣、寫文案、做圖片、預覽、確認、發佈」。帳號登入仍由使用者本人在 Chrome 完成，Skill 不保存密碼、Cookie 或 Token。

## 1. 這是什麼？

Social Browser Publisher 是一個可安裝到 Codex 的社群內容工作 Skill。它可以先研究近期熱門主題，再依照目前使用者或品牌自己的語氣，分別製作 Instagram、Facebook、Threads 適用的文案與圖片小卡，最後透過使用者已登入的 Chrome 預覽或發佈。

這不是一個內建固定作者語氣的文案模板。每位使用者都會建立自己的私人 profile；如果尚未訓練語氣，Skill 只會先提供中性草稿，不會模仿講師、Skill 作者、其他學員或範例人物。

## 2. 可以做到什麼？

### 2.1 搜尋近期熱門內容

- 搜尋指定期間內的近期話題，例如今天、24 小時、7 天或 30 天。
- 提供來源日期、直接連結、為什麼近期受到討論，以及資料限制。
- 通常先列出 5 個候選主題，讓使用者選擇後再寫文案。
- 以 A、B、C 表示證據可信度：A 為多個近期來源與直接討論證據；B 為可靠的當期來源或數個近期範例；C 為早期、較小眾或證據仍不完整的線索。
- 若看不到平台內的直接證據，會標明是「網路／新聞熱度」，不會冒充 Instagram、Facebook 或 Threads 全站排行。
- 不複製其他創作者的標題、笑話、文案或特色版面，只整理事實、問題與討論張力，再發展成使用者自己的角度。

### 2.2 學習每位使用者自己的語氣

- 分析使用者貼上的文章，或使用者明確授權讀取的本人社群頁面。
- 學習語氣、句子長度、段落節奏、標點、Emoji、Hashtag、開場、結尾與行動呼籲習慣。
- 支援同一台電腦管理多個人或品牌；每個 profile 完全分開。
- 使用者的修正優先於系統分析。例如使用者說「不要這麼多 Emoji」，之後會以這個修正為準。

### 2.3 依平台撰寫不同版本

- Instagram：適合搭配圖片或影片，重點放在開場、短段落、CTA 與適量 Hashtag。
- Facebook：可保留較完整的故事、說明與觀點，在情境或論點轉換時換段。
- Threads：使用較精簡、對話感明確的文字；較長內容會分成 2 至 4 個閱讀節奏，必要時才拆成多篇串文。
- 不會把同一份文字機械式貼到所有平台，除非使用者明確要求完全相同。

### 2.4 自動整理分行分段

- 依照想法、時間、情境、例子與行動呼籲的變化自然換段。
- 一般段落維持一個主要概念，避免整篇變成一大面文字牆。
- 不會把每一句都機械式換行，避免產生像樓梯一樣的零碎文案。
- 預覽畫面顯示的空行就是準備輸入平台的空行。
- 發佈前會重新讀回 composer 內的文字，核對內容與段落是否和核准版本一致。

### 2.5 製作 IG／FB 圖片小卡

- 可以把貼文重點轉成圖片小卡、封面或輪播內容。
- Instagram 直式貼文預設建議 1080 × 1350、4:5 比例。
- 重要標題、Logo 與 footer 會保留安全邊界，避免裁切。
- 圖卡只放精簡重點，完整說明保留在貼文文案。
- 產生後一定先顯示實際圖片；核准文字不等於自動核准另一張圖片。

### 2.6 規劃內容與回顧成效

- 可建立 14 天內容策略，安排教育、故事、產品／服務、社群提問、流程證明與輕互動等內容。
- 會查看近期已使用的熱門角度，減少短期內重複相同主題。
- 可依使用者提供或授權查看的數據，回顧觸及、留言品質、收藏、分享、點擊或後續成果。
- 不會宣稱有保證爆文的公式，也不會用單一數字比較目的不同的貼文。

### 2.7 透過已登入的 Chrome 安全發佈

- 使用 Chrome 目前可見、已登入的 Instagram、Facebook 或 Threads 帳號。
- 若尚未登入、需要驗證碼、Captcha 或帳號切換，會停下來請使用者親自操作。
- 發佈前再次核對可見帳號、目的地、文字、段落、圖片、順序、裁切與跨發開關。
- 可先執行 dry run，走到最後「分享／發佈」按鈕前停止，不會真的送出。
- 只有使用者針對剛剛預覽的內容明確說「發」、「發布」或「確認發佈」，才會按下最後按鈕。
- 發佈後會查看成功狀態，並在可行時開啟個人頁或貼文再次核對；只按到按鈕不等於已確認成功。

## 3. 安全與隱私設計

### Skill 不會保存的資料

- Instagram、Facebook、Threads 密碼
- 兩步驟驗證碼、備用碼或復原碼
- Cookie、Session、瀏覽器 Profile 資料
- Access Token、Refresh Token、API Key 或 App Secret
- 私人訊息、無關分頁或瀏覽紀錄

登入資料由 Chrome 自己管理。Codex 只在使用者授權的任務範圍內查看目前網頁上可見的帳號與操作介面。

### 每位使用者的私人資料放在哪裡？

```text
~/.config/codex-social-publisher/profiles/<profile-id>/
```

每個 profile 包含：

- `voice-profile.md`：語氣特徵與使用者修正
- `brand-profile.md`：受眾、目標、品牌資料與禁區
- `content-plan.md`：內容規劃與結果紀錄
- `trend-log.md`：已研究與採用的熱門主題摘要

這些檔案存放在安裝的 Skill 外面，不會被放進 GitHub 或下載 ZIP。macOS／Linux 上的私人資料夾權限為 `0700`，檔案權限為 `0600`。

### 「發」的授權範圍

「發」只授權它前面剛預覽的那一批內容。它不代表：

- 以後所有貼文都能自動發
- 其他尚未預覽的平台也能發
- 修改過的文字或圖片仍沿用舊核准
- 可以自動打開未授權的跨平台分享
- 可以大量排程、洗版或重複發文

若文字、段落、圖片、帳號、平台、裁切或目的地有實質變更，必須重新預覽並再次確認。

## 4. 安裝前準備

請先確認：

1. 電腦已安裝 Codex。
2. 已安裝 Google Chrome。
3. Codex 的 **Settings → Computer use** 已啟用 ChatGPT Chrome 擴充功能。
4. Instagram、Facebook、Threads 由使用者本人先在 Chrome 登入。
5. 建議建立獨立 Chrome 使用者，例如 `Codex Social`，讓社群登入與信箱、網銀及其他私人網站分開。

## 5. 安裝 Skill

在終端機執行：

```bash
python3 ~/.codex/skills/.system/skill-installer/scripts/install-skill-from-github.py \
  --repo jacky391977/social-browser-publisher \
  --path social-browser-publisher
```

安裝完成後，重新啟動 Codex，或開啟一個新的對話。

GitHub 下載頁：  
https://github.com/jacky391977/social-browser-publisher/releases/tag/v1.1.1

ZIP 直接下載：  
https://github.com/jacky391977/social-browser-publisher/releases/download/v1.1.1/social-browser-publisher-v1.1.1.zip

學員只需安裝 `social-browser-publisher`，不需要另外安裝舊 `social-post` 或另一個熱門搜尋 Skill。

## 6. 第一次安全設定

### 步驟 1：建立本機設定

```bash
python3 ~/.codex/skills/social-browser-publisher/scripts/init_config.py
```

這裡只填寫 Chrome 顯示名稱、目前使用者代號，以及預期的 IG／FB／Threads 帳號或目的地名稱。請勿輸入密碼、Token 或 Cookie。

### 步驟 2：建立使用者 profile

```bash
python3 ~/.codex/skills/social-browser-publisher/scripts/init_profile.py --profile-id default
```

`profile-id` 只能使用小寫英文字母、數字、底線或連字號。例如：

```bash
python3 ~/.codex/skills/social-browser-publisher/scripts/init_profile.py --profile-id fruit-store
python3 ~/.codex/skills/social-browser-publisher/scripts/init_profile.py --profile-id bakery-owner
```

### 步驟 3：選擇目前要使用的 profile

```bash
python3 ~/.codex/skills/social-browser-publisher/scripts/select_profile.py --profile-id fruit-store
```

切換 profile 不會清除 IG、FB、Threads 的目的地設定。正式發文前仍會從 Chrome 可見畫面重新核對帳號。

### 步驟 4：執行安全檢查

```bash
python3 ~/.codex/skills/social-browser-publisher/scripts/doctor.py
```

看到「Doctor：通過」代表設定檔格式與私人檔案權限沒有發現問題。網站是否已登入，仍要從 Chrome 畫面確認。

## 7. 上傳圖片前的 Chrome 權限

若要將本機圖片或影片上傳 Instagram／Facebook，請完成一次以下設定：

1. 在 Chrome 網址列輸入 `chrome://extensions/`。
2. 找到 ChatGPT 擴充功能，點「詳細資料」。
3. 開啟「允許存取檔案網址」（Allow access to file URLs）。
4. 關掉權限開啟前已經存在的 IG／FB 建立貼文視窗或檔案選擇視窗。
5. 回到 Codex，重新開始一次全新的發佈任務，讓系統開啟新的 composer。

> 重要：開啟權限後不要沿用舊 composer。舊視窗可能仍然沒有檔案存取能力，導致圖片無法上傳或重複操作。

純文字 Threads 貼文不需要這個本機檔案權限。

## 8. 教 Skill 學會你的語氣

建議提供 8 至 20 篇具有代表性的本人貼文，內容可包含日常、知識、產品、故事與互動貼文。請排除轉貼文章、別人的留言，以及由其他公司代寫但不代表你理想語氣的內容。

可直接使用以下指令：

```text
使用 $social-browser-publisher，目前 profile-id 是 fruit-store。
請只分析我接下來提供的本人貼文，建立我的語氣設定檔。
先告訴我三個最明顯的語氣特徵，再寫一篇中性主題測試草稿，不要發文。
```

如果想授權 Codex 從已登入 Chrome 讀取本人頁面，請清楚說明是哪個帳號或網址：

```text
使用 $social-browser-publisher。
我授權你從目前已登入 Chrome 的這個 Threads 個人頁面分析我自己的公開貼文，只建立 fruit-store 的語氣設定，不要讀私訊、其他分頁，也不要發文。
```

看到測試草稿後，可以直接修正：

```text
整體方向正確，但我平常不使用驚嘆號，Emoji 一篇最多一個，結尾不要每次都問問題。請更新我的語氣設定，再給我一篇測試稿。
```

## 9. 搜尋近期熱門主題

一個清楚的搜尋指令最好包含：主題、平台、受眾、地區與時間範圍。

```text
使用 $social-browser-publisher，搜尋最近 7 天台灣水果相關的熱門討論。
受眾是一般家庭消費者，目標平台是 Threads 與 Instagram。
列出 5 個候選主題、來源日期與直接連結、A/B/C 可信度、證據限制，以及適合 fruit-store 的原創切入角度。先不要寫完整文案，也不要發布。
```

Skill 會先讓使用者選擇角度，不會把 5 個候選全部自動寫成貼文或直接發出。若平台公開搜尋受限，結果可能只能證明「網路／新聞正在討論」，不能證明是平台全站熱門排行。

選定後可以接著說：

```text
選第 2 個主題。請用 fruit-store 的語氣分別寫 IG、Facebook、Threads 版本，保留自然分段，先完整預覽，不要發布。
```

## 10. 產生三平台文案

```text
使用 $social-browser-publisher，以 fruit-store 的語氣寫這個主題。
請分別產生 Instagram、Facebook、Threads 版本，事實與價格保持一致，但依平台調整長度和節奏。
每一版都要自然分行分段，先顯示完整預覽，不要發布。
```

可指定的常見條件包括：

- 貼文目的：教育、品牌故事、產品介紹、促銷、社群互動
- 目標受眾：新客、回購客、在地居民、企業客戶
- 文字長度：短版、中版、長版
- CTA：留言、私訊、到店、點擊連結、收藏
- Emoji 與 Hashtag 數量
- 禁止使用的字詞、承諾、敏感主題或價格資訊

## 11. 製作圖片小卡

```text
使用 $social-browser-publisher，把剛剛核准的重點做成 1080×1350、4:5 的 IG 圖片小卡。
保留品牌色，主標題要讓手機看得清楚，文字不要貼近邊緣。
先顯示實際圖片、IG 文案與發佈帳號，不要發布。
```

如果沒有品牌資料，Skill 會先詢問必要的顏色、Logo、字體或圖片方向，不會自行捏造品牌 Logo、客戶成果、產品外觀、認證或見證。

## 12. 先跑 dry run

第一次使用或網站介面改版後，建議先執行 dry run：

```text
使用 $social-browser-publisher，對剛剛核准的 IG 圖片與文案跑一次 dry run。
核對可見帳號、圖片上傳、4:5 裁切、原始色彩、文案分段與 Facebook／Threads 跨發開關。
停在最後「分享」按鈕前，不要發布。
```

dry run 可以驗證流程，但不會按下真正建立貼文的最後按鈕。

## 13. 正式發佈

標準流程如下：

1. Codex 顯示每個平台的完整文案、段落、圖片、帳號與目的地。
2. 使用者檢查內容，確認目前畫面清楚標示「尚未發布」。
3. 使用者針對這一批預覽明確說「發」。
4. Skill 在每個平台按下最後按鈕前，再次核對可見帳號與未授權的跨發開關。
5. 發佈後確認可見成功訊息，並在可行時到個人頁查看貼文與取得連結。
6. 每個平台分別回報：`已發布`、`未發布`、`需登入`、`帳號不符` 或 `失敗／狀態不明`。

如果發佈後結果不明，Skill 會先查看目的地，確認是否已經出現相同貼文，不會直接再次按下「分享」造成重複發佈。

## 14. 各平台注意事項

### Instagram

- 動態貼文需要圖片或影片。
- 1080 × 1350 圖卡需明確選擇 4:5，並確認標題與 footer 沒有被裁切。
- 預設保留「原始」色彩，不會自行套濾鏡。
- Instagram 可能預設開啟 Facebook 分享；若 Facebook 不在這次授權內，只關閉「此貼文」的分享，不修改所有貼文的全域設定。
- 圖片上傳完成後可能需要等待裁切畫面，不能因介面暫時沒有更新就重複上傳。

### Facebook

- 發佈前要確認是個人檔案、粉絲專頁或社團中的哪一個目的地。
- 保留目前可見的貼文受眾，除非使用者明確要求修改。
- 較長故事會在情境或觀點變化時分段，避免整篇擠成一段。

### Threads

- 需要單獨確認 Threads 可見帳號，不能只假設它和 Instagram 相同。
- 很短的單一想法可以維持一段；較長內容會分成 2 至 4 個閱讀節奏。
- 若內容需要拆成串文，會先依順序預覽並核准每一段。

## 15. 常用指令範本

### 建立 14 天內容計畫

```text
使用 $social-browser-publisher，為 fruit-store 建立 14 天內容計畫。
平台是 IG、Facebook、Threads，每週發 4 天，教育、產品、品牌故事與互動內容要平衡。
先給我計畫，不要發布。
```

### 只寫草稿，不操作瀏覽器

```text
使用 $social-browser-publisher，只產生三平台草稿與圖片方向，不要開 Chrome，也不要發布。
```

### 修改文字後重新預覽

```text
把價格那一段拿掉，結尾改得更自然，Emoji 留一個。重新顯示 IG、Facebook、Threads 完整版本；舊的發布確認作廢。
```

### 發佈剛剛核准的一批

```text
發
```

只有在上一則訊息已完整顯示帳號、平台、文案、段落與圖片時，這個「發」才代表同意該批內容。

### 回顧成效

```text
使用 $social-browser-publisher，依我提供的最近貼文數據回顧成效。
請分開看觸及、留言品質、收藏、分享與點擊，提出下一週的調整建議，不要直接發布。
```

## 16. 常見問題排除

### Codex 找不到 Skill

重新啟動 Codex，或開啟新對話，再確認 Skill 安裝目錄是：

```text
~/.codex/skills/social-browser-publisher/
```

### 無法控制 Chrome

到 Codex 的 **Settings → Computer use** 確認 ChatGPT Chrome 擴充功能已啟用。若 Chrome 控制能力不可用，Skill 不會改用另一個瀏覽器假裝完成發佈。

### 顯示「需登入」

請使用者直接在 Chrome 完成登入、驗證碼或 Captcha，再回到 Codex 說「已登入，請繼續」。不要把帳號密碼或驗證碼貼到聊天中。

### IG 圖片沒有上傳

確認 Chrome 擴充功能已開啟「允許存取檔案網址」。如果是剛開啟權限，必須關閉舊 composer，重新開一個全新的發佈流程。

### 顯示「帳號不符」

目前 Chrome 可見帳號和設定的預期目的地不同。請自行在 Chrome 切換到正確帳號，或重新執行 `init_config.py` 修正非敏感的目的地名稱。

### 語氣不像本人

不要直接發布。提供更多本人貼文，指出哪裡不對，並要求更新 `User corrections`。必要時重新建立測試草稿，確認後再使用。

### 熱門主題證據不足

縮小主題、地區或時間範圍，或明確授權 Skill 使用已登入 Chrome 查看平台近期搜尋。若平台仍受限，應把候選視為探索線索，而不是確認的全站熱門排行。

### 發佈結果不明

不要立刻再說一次「發」。先要求 Skill 查看目的地是否已出現相同貼文，排除重複後再決定下一步。

## 17. 使用限制

Social Browser Publisher 適合一般人工頻率的社群內容工作，不適合：

- 大量無人值守排程或大量帳號控制
- 自動按讚、自動追蹤或大量留言
- 未經請求的私訊、廣告或互動
- 洗版、重複發佈或繞過平台安全機制
- 以有限樣本冒充完整平台排行榜
- 把新聞、零售價或社群貼文當成另一種未經證實的市場資料

社群網站介面會改版，因此實際操作以當下可見 UI 為準。若平台要求登入、驗證、同意條款或帳號切換，必須由使用者本人完成。

## 18. 發佈前快速檢查表

- [ ] 目前使用的是正確 `profile-id`
- [ ] Chrome 顯示的是正確帳號或粉絲專頁
- [ ] 熱門主題有來源日期、連結與證據限制
- [ ] 文案沒有抄襲其他創作者
- [ ] IG、Facebook、Threads 各自使用適合的平台版本
- [ ] 文案已自然分行分段，空行與預覽一致
- [ ] 圖片是核准的檔案與順序，4:5 裁切沒有切字
- [ ] 未授權的跨平台分享已關閉
- [ ] 畫面清楚標示尚未發布，再由使用者說「發」
- [ ] 發佈後確認成功狀態與目的地貼文

## 19. 建議的新手完整流程

1. 安裝 Skill 並重新啟動 Codex。
2. 啟用 Chrome 擴充功能，登入要使用的社群帳號。
3. 執行 `init_config.py`、`init_profile.py`、`select_profile.py`、`doctor.py`。
4. 提供本人貼文，完成語氣分析與測試草稿修正。
5. 搜尋指定期間的 5 個熱門候選，選定一個角度。
6. 產生 IG、Facebook、Threads 三個平台版本並檢查分段。
7. 如需 IG／FB 圖文，先產生並查看實際圖片小卡。
8. 第一次先跑 dry run，停在最後按鈕前。
9. 確認帳號、內容、圖片、裁切與跨發開關後說「發」。
10. 查看每個平台的結果與貼文連結。
