# Platform-specific writing

Use the same approved facts and active user's voice, but compose a native version for each requested platform. Do not paste one identical block everywhere unless the user explicitly asks for identical text.

## Shared rules

- Preserve factual claims, offer details, dates, prices, and links exactly as approved.
- Never manufacture personal stories, customer quotes, scarcity, results, profanity, controversy, or endorsements to make a post more engaging.
- The user's voice profile outranks generic growth formulas. If the user rarely uses emoji, hashtags, hype, or calls to action, do not add them by default.
- Treat platform limits and UI behavior as changeable. Check the current composer when exact limits matter.
- Show each full version with its destination label before publishing.

## Readable line breaks and paragraphs

Every preview must show the exact line breaks that will be entered in the platform composer. Use blank lines to separate ideas; do not return or publish an unbroken wall of text unless the active user's verified style and the short length genuinely make one paragraph clearer.

- Start a new paragraph when the idea, time, scene, example, or call to action changes.
- Keep one main idea per paragraph. For ordinary social posts, one to three sentences per paragraph is a useful default, adjusted to the user's own rhythm.
- Do not put every sentence on a new line mechanically. Line breaks should create readable beats, not a staircase of fragments.
- Use plain text in the final composer. Markdown headings, bullets, and emphasis markers appear only when the platform and user intentionally want them.
- Preserve user-approved wording while improving spacing. If moving text changes emphasis or meaning, show a new preview.

## Instagram

- Lead with the strongest useful idea because captions may be visually truncated.
- Pair the caption with approved image/video media; feed posts require media.
- Use readable line breaks and only the hashtag style supported by the user's profile or request.
- Links in captions may not be directly actionable; do not promise clickability without checking the current UI.
- For image cards, keep the card concise and move supporting context into the caption.
- A useful caption shape is: hook, blank line, short context/body paragraphs, blank line, question or call to action, blank line, hashtags. Omit sections the post does not need.

## Facebook

- Use the destination's normal voice: personal profile, Page, and group posts may differ.
- Narrative and context can be longer when the user's samples support it.
- Keep hashtags restrained unless the user's own profile regularly uses them.
- Do not change audience/privacy or add a group/Page destination without explicit instruction.
- Break longer narrative text at scene or argument changes. Keep the opening, body, and closing visually distinct when that improves scanning.

## Threads

- Prefer conversational, compact language with a clear opinion, observation, or question.
- Keep paragraphs short. A very short single thought may remain one paragraph; longer posts should use two to four readable beats before becoming a multi-post thread.
- Split a long idea into a reviewed thread only when needed, at sentence boundaries, with each segment previewed in order.
- Do not force outrage, conflict, slang, or profanity. Use them only when present in the user's approved voice and appropriate to the request.
- Verify the visible Threads account because desktop account switching may differ from Instagram.

## Final self-check

Before previewing, ask:

1. Does this sound like the active user rather than the Skill author or a generic marketer?
2. Did every platform version preserve the same approved facts?
3. Did any unapproved personal story, promise, link, tag, or destination appear?
4. Would removing the profile-specific traits make it generic? If yes, restore only traits supported by the profile.
5. Are paragraphs separated at real idea changes, with no accidental wall of text or excessive one-line fragments?
